Теперь LeetTest работает с сервисами без reflection, сам проверяет пороги и сравнивает два прогона. [English](#english) · [Deutsch](#deutsch) · [简体中文](#简体中文)

## Новое

- **Сервисы без reflection** — схема методов берётся из файлов `.proto` или protoset.
- **Пороги** — секция `pass` задаёт пределы латентности и ошибок; прогон, который в них не уложился, завершается с отдельным кодом выхода — готово для CI.
- **Сравнение прогонов** — `leettest compare before.json after.json` показывает, насколько упала ёмкость или вырос p99.
- **Паспорт прогона** — отчёт хранит, на какой машине и с каким конфигом он сделан; `-json-file` пишет отчёт в файл.
- **Случайный порядок данных** — запросы из файла идут в случайном порядке, который можно повторить, или без повторов.

Ещё: p99.9 по методу, сжатие gzip, свой лимит ошибок в поиске точки отказа, предупреждение, когда CPU не хватает самому генератору, установка одной командой на Linux и macOS.

## Исправлено

- На машине с одним ядром генератор больше не добавляет к латентности свою задержку при 500 rps и выше.
- Ответ на unary-вызов без сообщения или с лишним сообщением теперь `bad response`, а не ошибка цели.
- Ошибка о не заданной `${ENV}` говорит, как её задать.

## При обновлении

- Одно имя якоря YAML (`&a`), заданное дважды, теперь ошибка конфига: раньше поле могло молча получить чужое значение. Переименуйте один из якорей.
- Служебные заголовки (`content-type`, `te`, `connection` и подобные) в метаданных теперь отклоняются до старта.

## English

LeetTest now works with services without reflection, checks thresholds itself and compares two runs.

### New

- **Services without reflection** — the schema of the methods is taken from `.proto` files or a protoset.
- **Thresholds** — the `pass` section sets limits on latency and errors; a run that does not stay within them ends with its own exit code — ready for CI.
- **Run comparison** — `leettest compare before.json after.json` shows how much the capacity fell or p99 rose.
- **Run passport** — the report keeps which machine and which config it was made with; `-json-file` writes the report to a file.
- **Random order of data** — requests from the file go in a random order that can be repeated, or without repeats.

Also: p99.9 per method, gzip compression, your own error limit in the breaking-point search, a warning when the generator itself runs short of CPU, one-command install on Linux and macOS.

### Fixed

- On a one-core machine the generator no longer adds its own delay to latency at 500 rps and above.
- A reply to a unary call with no message or with an extra message is now `bad response`, not a target error.
- The error about an unset `${ENV}` says how to set it.

### Upgrading

- A single YAML anchor name (`&a`) defined twice is now a config error: before, a field could silently get another anchor's value. Rename one of the anchors.
- Reserved headers (`content-type`, `te`, `connection` and the like) in metadata are now rejected before the start.

## Deutsch

LeetTest arbeitet jetzt mit Diensten ohne Reflection, prüft Schwellen selbst und vergleicht zwei Läufe.

### Neu

- **Dienste ohne Reflection** — das Schema der Methoden kommt aus `.proto`-Dateien oder einem Protoset.
- **Schwellen** — der Abschnitt `pass` setzt Grenzen für Latenz und Fehler; ein Lauf, der sie nicht einhält, endet mit einem eigenen Exit-Code — bereit für CI.
- **Läufe vergleichen** — `leettest compare before.json after.json` zeigt, wie stark die Kapazität gefallen oder der p99 gestiegen ist.
- **Pass des Laufs** — der Bericht hält fest, auf welcher Maschine und mit welcher Konfiguration er entstand; `-json-file` schreibt den Bericht in eine Datei.
- **Zufällige Reihenfolge der Daten** — Anfragen aus der Datei gehen in zufälliger, wiederholbarer Reihenfolge oder ohne Wiederholungen.

Außerdem: p99.9 je Methode, gzip-Kompression, eigene Fehlergrenze bei der Suche nach dem Bruchpunkt, eine Warnung, wenn dem Generator selbst die CPU fehlt, Installation mit einem Befehl unter Linux und macOS.

### Behoben

- Auf einer Maschine mit einem Kern fügt der Generator der Latenz ab 500 rps keine eigene Verzögerung mehr hinzu.
- Eine Antwort auf einen unären Aufruf ohne Nachricht oder mit einer zusätzlichen Nachricht ist jetzt `bad response`, kein Fehler des Ziels.
- Der Fehler zu einer nicht gesetzten `${ENV}` sagt, wie man sie setzt.

### Beim Update

- Ein YAML-Anker-Name (`&a`), der zweimal vergeben wird, ist jetzt ein Konfigurationsfehler: Früher konnte ein Feld stillschweigend den Wert eines fremden Ankers bekommen. Benennen Sie einen der Anker um.
- Reservierte Header (`content-type`, `te`, `connection` und ähnliche) in den Metadaten werden jetzt vor dem Start abgelehnt.

## 简体中文

LeetTest 现在支持没有 reflection 的服务，能自己检查阈值，并比较两次运行。

### 新功能

- **没有 reflection 的服务** —— 方法的结构取自 `.proto` 文件或 protoset。
- **阈值** —— `pass` 段设置延迟和错误的限值；未达标的运行会以单独的退出码结束——可直接用于 CI。
- **运行对比** —— `leettest compare before.json after.json` 显示容量下降了多少或 p99 上升了多少。
- **运行护照** —— 报告记录它是在哪台机器、用哪份配置得出的；`-json-file` 把报告写入文件。
- **数据的随机顺序** —— 文件中的请求按可重复的随机顺序发送，或不重复发送。

另外：按方法的 p99.9、gzip 压缩、崩溃点搜索中可自定义的错误上限、压测机自身 CPU 不足时的提示、在 Linux 和 macOS 上一条命令安装。

### 修复

- 在单核机器上，请求速率达到 500 rps 及以上时，压测机不再给延迟额外加上自身的延迟。
- 对 unary 调用的应答没有消息或多出消息时，现在归为 `bad response`，而不是目标的错误。
- 未设置 `${ENV}` 的报错会说明如何设置。

### 升级须知

- 同一个 YAML 锚点名（`&a`）定义两次，现在是配置错误：此前某个字段可能悄悄取到别的锚点的值。请重命名其中一个锚点。
- 元数据中的保留头（`content-type`、`te`、`connection` 等）现在会在启动前被拒绝。
