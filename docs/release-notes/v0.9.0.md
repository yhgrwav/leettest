Теперь можно нагрузить цепочку вызовов: вызов и шаги за ним идут одной итерацией, шаг берёт значение из ответа предыдущего, а отчёт показывает каждый шаг отдельно. [English](#english) · [Deutsch](#deutsch) · [简体中文](#简体中文)

## Новое

- **Сценарий** — `scenario` и `steps` у вызова: вызов и шаги за ним идут по порядку одной итерацией, `rps` считает итерации, у каждого шага своё тело (`data`). Пока без `pass`, поиска точки отказа и `-dry-run`; один метод дважды в сценарии нельзя.
- **Разные запросы в шаге** — шаг берёт `{{seq}}` и `{{uuid}}` (`templates: true`) или тело из файла (`dataset`); `{{seq}}` один на всю итерацию.
- **Значение из ответа — в следующий шаг** — `extract` называет поле ответа, а следующий шаг подставляет его как `{{extract.<имя>}}`; значения живут в одной итерации, путь к полю проверяется до нагрузки, ответ без значения — `bad_response`.
- **Отчёт по сценарию** — блок сценария в текстовом и в JSON-отчёте: исходы итераций, их задержка и строка на каждый шаг (дошло, не удалось, прервано, не ушло).

Ещё: вердикт `gomaxprocs` в прогоне `generator_late` называет квоту CPU, когда она ниже числа CPU.

- Заметка о том, сколько ожидание на стороне клиента добавило к p99, больше не печатает отрицательное время.

## English

You can now load a chain of calls: a call and the steps after it run as one iteration, a step takes a value from the previous reply, and the report shows every step on its own.

### New

- **Scenario** — `scenario` and `steps` on a call: the call and its steps run in order as one iteration, `rps` counts iterations, each step has its own body (`data`). Not yet with `pass`, the breaking-point search or `-dry-run`; one method cannot appear twice in a scenario.
- **Different requests in a step** — a step takes `{{seq}}` and `{{uuid}}` (`templates: true`) or a body from a file (`dataset`); `{{seq}}` is one per iteration.
- **A value from a reply goes into the next step** — `extract` names a field of the reply, and a later step uses it as `{{extract.<name>}}`; values live in one iteration, the field path is checked before the load, a reply without the value is a `bad_response`.
- **The scenario report** — a scenario block in the text and in the JSON report: the iterations' outcomes, their latency and a line per step (reached, failed, aborted, not sent).

Also: the `gomaxprocs` verdict of a `generator_late` run names the CPU quota when it is below the number of CPUs.

### Fixed

- The note on how much client-side waiting added to p99 no longer prints a negative time.

## Deutsch

Sie können jetzt eine Kette von Aufrufen belasten: Ein Aufruf und die Schritte danach laufen als eine Iteration, ein Schritt übernimmt einen Wert aus der vorherigen Antwort, und der Bericht zeigt jeden Schritt für sich.

### Neu

- **Szenario** — `scenario` und `steps` an einem Aufruf: Der Aufruf und seine Schritte laufen der Reihe nach als eine Iteration, `rps` zählt Iterationen, jeder Schritt hat seinen eigenen Body (`data`). ## 简体中文

现在可以对一串调用施加负载：一个调用和它后面的步骤作为一次迭代运行，后一步使用前一步回复中的值，报告会把每一步单独列出。

### 新功能

- **场景** — 调用上的 `scenario` 和 `steps`：调用及其步骤按顺序作为一次迭代运行，`rps` 统计迭代数，每一步有自己的请求体（`data`）。暂不支持与 `pass`、断点搜索或 `-dry-run` 一起使用；同一个方法不能在一个场景中出现两次。
- **步骤中的不同请求** — 步骤可使用 `{{seq}}` 和 `{{uuid}}`（`templates: true`），或来自文件的请求体（`dataset`）；`{{seq}}` 每次迭代只有一个。
- **回复中的值传给下一步** — `extract` 指明回复中的字段，后面的步骤以 `{{extract.<名称>}}` 使用它；值只在一次迭代内有效，字段路径在加载前检查，回复中没有该值则为 `bad_response`。
- **场景报告** — 文本报告和 JSON 报告中的场景块：迭代的结果、延迟，以及每一步一行（到达、失败、中断、未发出）。

另外：`generator_late` 运行中的 `gomaxprocs` 结论在 CPU 配额低于 CPU 数量时会指出该配额。

### 修复

- 关于客户端等待为 p99 增加了多少的说明，不再打印负的时间。
