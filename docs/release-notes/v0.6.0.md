Теперь прогон можно смотреть в Grafana, а отчёт показывает, как менялась латенси по ходу нагрузки; в запросах появляются уникальные поля. [English](#english) · [Deutsch](#deutsch) · [简体中文](#简体中文)

## Новое

- **Метрики в Prometheus** — `export.prometheus.listen` (или флаг `-metrics-listen`) отдаёт `/metrics`, пока идёт нагрузка; адрес по умолчанию не задан, а выход после прогона задерживается на 15 с (`linger`), чтобы Prometheus успел снять итог.
- **Латенси по времени** — под таблицей каждого метода блок `over time`: темп, доля отказов, p50 и p99 по окнам прогона, не больше 12 строк; видно, когда p99 пошёл вверх, а не только чем всё кончилось.
- **Уникальные поля в запросах** — `templates: true` подставляет в `data` `{{uuid}}` (новый на каждый запрос) и `{{seq}}` (номер запроса с 1).

Ещё: план, который не помещается в 32-битное поле с `{{seq}}`, отклоняется до первого запроса.

## English

You can now watch a run in Grafana, the report shows how latency changed over the load, and requests can carry unique fields.

### New

- **Prometheus metrics** — `export.prometheus.listen` (or the `-metrics-listen` flag) serves `/metrics` while the load runs; there is no default address, and the exit after a run is held for 15 s (`linger`) so Prometheus can scrape the final numbers.
- **Latency over time** — under each method's table an `over time` block: rate, failure share, p50 and p99 per window of the run, at most 12 rows; you see when p99 started to climb, not only how it ended.
- **Unique fields in requests** — `templates: true` fills `{{uuid}}` (new for every request) and `{{seq}}` (the request number from 1) into `data`.

Also: a plan that does not fit a 32-bit field holding `{{seq}}` is refused before the first request.

## Deutsch

Ein Lauf lässt sich jetzt in Grafana beobachten, der Bericht zeigt, wie sich die Latenz während der Last verändert hat, und Anfragen können eindeutige Felder tragen.

### Neu

- **Prometheus-Metriken** — `export.prometheus.listen` (oder das Flag `-metrics-listen`) liefert `/metrics`, solange die Last läuft; es gibt keine Standardadresse, und der Ausstieg nach dem Lauf wird um 15 s (`linger`) verzögert, damit Prometheus das Endergebnis abholen kann.
- **Latenz über die Zeit** — unter der Tabelle jeder Methode ein Block `over time`: Rate, Fehleranteil, p50 und p99 je Zeitfenster des Laufs, höchstens 12 Zeilen; man sieht, wann p99 gestiegen ist, nicht nur, wie alles endete.
- **Eindeutige Felder in Anfragen** — `templates: true` setzt in `data` `{{uuid}}` (neu für jede Anfrage) und `{{seq}}` (die Anfragenummer ab 1) ein.

Außerdem: ein Plan, der nicht in ein 32-Bit-Feld mit `{{seq}}` passt, wird vor der ersten Anfrage abgelehnt.

## 简体中文

现在可以在 Grafana 里观察一次运行，报告会显示延迟在加压过程中如何变化，请求里也可以带上唯一的字段。

### 新功能

- **Prometheus 指标** — `export.prometheus.listen`（或标志 `-metrics-listen`）在加压期间提供 `/metrics`；没有默认地址，运行结束后的退出会延迟 15 秒（`linger`），让 Prometheus 来得及取走最终数字。
- **延迟随时间的变化** — 每个方法的表格下方有一个 `over time` 块：各时间窗口的速率、失败占比、p50 和 p99，最多 12 行；可以看到 p99 是何时开始上升的，而不只是最后的结果。
- **请求中的唯一字段** — `templates: true` 在 `data` 中填入 `{{uuid}}`（每个请求都是新的）和 `{{seq}}`（从 1 开始的请求编号）。

另外：放不进带 `{{seq}}` 的 32 位字段的计划，会在第一个请求之前被拒绝。
