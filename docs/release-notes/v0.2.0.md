Теперь LeetTest сам находит нагрузку, на которой сервис перестаёт справляться. Плюс разные запросы в
каждом вызове и несколько соединений. [English](#english) · [Deutsch](#deutsch) · [简体中文](#简体中文)

## Что нового

- **Поиск точки отказа.** Секция `load.breakpoint` вместо `rps` и `duration`: LeetTest поднимает
  нагрузку ступенями и называет, на какой ступени цель держалась и на какой сломалась. Ступень
  ломается от доли ошибок или от p99 (порог можно задать); сломанную ступень он повторяет и проверяет,
  что цель вернулась к прежнему p99. Если упёрся сам генератор, итог говорит об этом, а не о цели.
  Итог в отчёте и в JSON — из закрытого списка (`broke`, `broke_at_first`, `held_all`, `run_limit`,
  `stopped`, `invalid`) с причиной, у поиска есть живой экран.
- **Разные данные в каждом вызове.** `dataset: wallets.jsonl` у вызова: по JSON на строку, по порядку
  и по кругу. Файл проверяется до старта по схеме метода; ошибка называет строку и не печатает её
  содержимое. Отчёт говорит, сколько файла использовано.
- **Несколько соединений.** `app.connections: N` (1–256): вызовы идут по соединениям по кругу, имя с
  несколькими адресами раскладывается по ним. Отчёт показывает блок по соединениям — адрес, вызовы,
  доля отказов, p99 — так что мёртвый или медленный бэкенд за именем не усредняется.
- **`-plain`.** Без живого экрана и без диалога первого запуска: строка прогресса раз в секунду, как
  без терминала. Удобно по ssh и в скриптах.
- **Точнее про оборванные вызовы.** Если grpc-go потерял статус вызова после прозрачного повтора
  ([grpc-go#9443](https://github.com/grpc/grpc-go/issues/9443)), вызов — `cut off` без кода, который
  приписан цели; раньше он мог выглядеть ошибкой клиента или сбоем, присланным целью.
- **JSON** остаётся `schema_version` 1: поля добавлены (`mode`, `connections.per_connection`,
  `methods[].dataset`, `breakpoint.*`), в режиме поиска верхний объект другой — см.
  [справочник](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/ru/reference.md).

## Ограничения

Только unary. Нет разгона с нуля, порогов для CI и экспорта метрик —
[что будет дальше](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/ru/roadmap.md). Несколько
соединений делят вызовы по кругу между адресами имени; за L4-балансировщиком они не гарантируют
разные бэкенды. Мерьте с Linux рядом с целью.

Не хватает возможности — [напишите issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## English

LeetTest now finds the load at which a service stops coping by itself. Plus a different request on
each call and several connections.

### What is new

- **Breaking-point search.** A `load.breakpoint` section instead of `rps` and `duration`: LeetTest
  raises the load in steps and names the step the target held and the step it broke on. A step
  breaks on the share of errors or on p99 (the limit can be set); a broken step is repeated, and the
  target must come back to its earlier p99. If the generator itself hit a limit, the outcome says so
  instead of blaming the target. The outcome in the report and in JSON is from a closed list
  (`broke`, `broke_at_first`, `held_all`, `run_limit`, `stopped`, `invalid`) with a reason; the
  search has a live screen.
- **A different request on each call.** `dataset: wallets.jsonl` on a call: one JSON per line, in
  order and round and round. The file is checked against the method's schema before the start; an
  error names the line and does not print its content. The report says how much of the file was used.
- **Several connections.** `app.connections: N` (1–256): calls go round-robin over the connections,
  a name with several addresses is spread over them. The report shows a block per connection —
  address, calls, share failed, p99 — so a dead or slow backend behind the name is not averaged
  away.
- **`-plain`.** No live screen and no first-run dialog: a progress line once a second, as without a
  terminal. Handy over ssh and in scripts.
- **Sharper about cut-off calls.** When grpc-go loses a call's status after a transparent retry
  ([grpc-go#9443](https://github.com/grpc/grpc-go/issues/9443)), the call is `cut off` with no code
  attributed to the target; before, it could read as a client error or as a failure the target
  sent.
- **JSON** stays `schema_version` 1: fields were added (`mode`, `connections.per_connection`,
  `methods[].dataset`, `breakpoint.*`); in search mode the top-level object is different — see the
  [reference](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/en/reference.md).

### Limits

Unary only. No ramp-up from zero, CI thresholds or metrics export yet —
[what comes next](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/en/roadmap.md). Several
connections share calls round-robin over the addresses of a name; behind an L4 balancer they do not
guarantee different backends. Measure from Linux next to the target.

Missing something? [Open an issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## Deutsch

LeetTest findet jetzt selbst die Last, bei der ein Dienst nicht mehr zurechtkommt. Dazu eine andere
Anfrage bei jedem Aufruf und mehrere Verbindungen.

### Was neu ist

- **Suche nach dem Bruchpunkt.** Ein Abschnitt `load.breakpoint` statt `rps` und `duration`:
  LeetTest erhöht die Last in Stufen und nennt die Stufe, die das Ziel hielt, und die, auf der es
  brach. Eine Stufe bricht am Anteil der Fehler oder am p99 (die Grenze lässt sich setzen); eine
  gebrochene Stufe wird wiederholt, und das Ziel muss zum früheren p99 zurückkehren. Stieß der
  Generator selbst an eine Grenze, sagt das Ergebnis es, statt das Ziel zu beschuldigen. Das
  Ergebnis in Bericht und JSON stammt aus einer geschlossenen Liste (`broke`, `broke_at_first`,
  `held_all`, `run_limit`, `stopped`, `invalid`) mit einem Grund; die Suche hat eine Live-Ansicht.
- **Bei jedem Aufruf eine andere Anfrage.** `dataset: wallets.jsonl` am Aufruf: ein JSON pro Zeile,
  der Reihe nach und im Kreis. Die Datei wird vor dem Start gegen das Schema der Methode geprüft;
  ein Fehler nennt die Zeile und gibt ihren Inhalt nicht aus. Der Bericht sagt, wie viel der Datei
  benutzt wurde.
- **Mehrere Verbindungen.** `app.connections: N` (1–256): Aufrufe gehen reihum über die
  Verbindungen, ein Name mit mehreren Adressen wird darauf verteilt. Der Bericht zeigt einen Block
  je Verbindung — Adresse, Aufrufe, Anteil Fehler, p99 —, damit ein totes oder langsames Backend
  hinter dem Namen nicht untergemittelt wird.
- **`-plain`.** Keine Live-Ansicht und kein Dialog beim ersten Start: eine Fortschrittszeile pro
  Sekunde, wie ohne Terminal. Praktisch über ssh und in Skripten.
- **Genauer bei abgeschnittenen Aufrufen.** Verliert grpc-go den Status eines Aufrufs nach einem
  transparenten Wiederholen ([grpc-go#9443](https://github.com/grpc/grpc-go/issues/9443)), ist der
  Aufruf `cut off` ohne einen dem Ziel zugeschriebenen Code; zuvor konnte er wie ein Fehler des
  Clients oder wie ein vom Ziel gesendeter Fehler aussehen.- **JSON** bleibt `schema_version` 1: Felder kamen hinzu (`mode`, `connections.per_connection`,
  `methods[].dataset`, `breakpoint.*`); im Suchmodus ist das oberste Objekt ein anderes — siehe
  [Referenz](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/de/reference.md).

### Grenzen

Nur unär. Noch kein Hochfahren von null, keine CI-Schwellen, kein Metrik-Export —
[was als Nächstes kommt](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/de/roadmap.md).
Mehrere Verbindungen teilen die Aufrufe reihum auf die Adressen eines Namens auf; hinter einem
L4-Load-Balancer garantieren sie keine verschiedenen Backends. Messen Sie von Linux aus neben dem
Ziel.

Fehlt Ihnen etwas? [Eröffnen Sie ein Issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## 简体中文

LeetTest 现在能自己找出服务开始吃不消的负载。此外，每次调用可用不同的请求，并支持多条连接。

### 新功能

- **崩溃点搜索。** 用 `load.breakpoint` 段代替 `rps` 和 `duration`：LeetTest 分阶梯提高负载，指出目标
  在哪一阶撑住、在哪一阶崩溃。一个阶梯因错误比例或 p99 而判为崩溃（p99 上限可设置）；崩溃的阶梯会
  重复，目标必须回到先前的 p99。如果是压测机自身触到上限，结论会如实说明，而不是归咎于目标。报告和
  JSON 中的结论取自封闭列表（`broke`、`broke_at_first`、`held_all`、`run_limit`、`stopped`、
  `invalid`）并附原因；搜索有实时界面。
- **每次调用不同的请求。** 在调用上写 `dataset: wallets.jsonl`：每行一个 JSON，按顺序循环使用。文件在
  启动前按方法的结构检查；错误会指出行号，且不输出该行内容。报告会说明文件用了多少。
- **多条连接。** `app.connections: N`（1–256）：调用在连接间轮流分配，对应多个地址的名称会分摊到这些
  地址上。报告按连接给出一个块——地址、调用数、失败比例、p99——因此名称背后失效或变慢的后端不会被
  平均掉。
- **`-plain`。** 没有实时界面，也没有首次运行对话框：每秒一行进度，与无终端时相同。适合 ssh 和脚本。
- **对被截断的调用更准确。** 当 grpc-go 在透明重试后丢失调用的状态
  （[grpc-go#9443](https://github.com/grpc/grpc-go/issues/9443)），该调用归为 `cut off`，不再给目标
  记任何代码；此前它可能被当作客户端错误，或目标发来的故障。
- **JSON** 仍为 `schema_version` 1：新增了字段（`mode`、`connections.per_connection`、
  `methods[].dataset`、`breakpoint.*`）；搜索模式下顶层对象不同——见
  [参考](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/zh-CN/reference.md)。

### 限制

仅支持 unary。尚无从零爬坡、CI 阈值和指标导出——
[接下来会有什么](https://github.com/yhgrwav/leettest/blob/v0.2.0/docs/zh-CN/roadmap.md)。多条连接在名称
的各地址间轮流分配调用；在 L4 负载均衡器后面，不保证落到不同后端。请在目标旁边的 Linux 上测量。

缺少某项功能？[提交 issue](https://github.com/yhgrwav/leettest/issues/new/choose)。
