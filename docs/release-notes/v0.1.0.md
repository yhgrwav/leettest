Первая публичная версия: нагрузка на gRPC-сервис и отчёт, который не врёт, когда сервис
деградирует. [English](#english) · [Deutsch](#deutsch) · [简体中文](#简体中文)

## Что умеет

- **Нагрузка, похожая на настоящую.** Несколько unary-методов в одном прогоне, у каждого свой RPS и
  длительность. Вызовы уходят по расписанию, даже если предыдущие ещё не ответили.
- **Задержка, которая не прячет зависания.** Считается от момента, на который вызов был
  запланирован; p50/p90/p95/p99 и максимум по каждому методу, без усреднений.
- **Без `.proto`.** Методы и тело запроса берутся у сервиса через server reflection; тело пишется в
  конфиге обычным YAML и проверяется до старта.
- **Доступ к настоящим сервисам.** TLS, взаимный TLS, свой CA, `server_name`; заголовки с
  секретами из переменных окружения — их значения нигде не печатаются.
- **Ошибки — до первого вызова.** Строгий конфиг, проверка подключения и запаса на зависшую цель —
  с тем, что поменять.
- **Отчёт говорит, что случилось.** Вызовы по категориям (перегрузка, сбой цели, таймаут, обрыв,
  недоступность и др.); коды ошибок отдельно «от цели» и «от клиента»; «при 300 RPS 40% вызовов
  не получили ответа, с 25-й секунды — ни один»; таймаут показан как нижняя граница (`>500ms`), а
  не числом; прогрев отдельно.
- **Видна доля самого генератора.** Опоздание старта вызовов, ожидание соединения и стрима, p99 без
  них — и что из этого держит хвост.
- **Честная недействительность.** Если числа не про цель (упор в потолок, ничего не измерено,
  слишком грубые часы машины), прогон объявляется недействительным, код выхода 2. Ctrl+C
  останавливает мягко и всё равно печатает отчёт.
- **Для людей и для скриптов.** Живой экран в терминале, строка прогресса без терминала, JSON
  (`schema_version` 1) для CI.
- **Попробовать без своего сервиса.** Эталонный стенд с известным поведением, готовые примеры на
  каждый режим ([быстрый старт](https://github.com/yhgrwav/leettest/blob/main/docs/ru/quickstart.md)),
  встроенная фальшивая цель `-fake`.

## Ограничения

Одно соединение — за балансировщиком нагрузку получает один бэкенд. Только unary. Нет разгона,
порогов для CI и экспорта метрик — [что будет дальше](https://github.com/yhgrwav/leettest/blob/main/docs/ru/roadmap.md).
Мерьте с Linux рядом с целью.

Не хватает возможности — [напишите issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## English

The first public version: load on a gRPC service and a report that does not lie while the service
degrades.

### What it does

- **Load that looks like production.** Several unary methods in one run, each at its own RPS and
  duration. Calls go out on schedule even if earlier ones have not answered.
- **Latency that does not hide stalls.** Counted from the moment each call was scheduled for;
  p50/p90/p95/p99 and max per method, never averaged.
- **No `.proto`.** Methods and request bodies come from the service through server reflection; the
  body is plain YAML in the config, checked before the start.
- **Access to real services.** TLS, mutual TLS, a custom CA, `server_name`; headers with secrets
  from environment variables, their values printed nowhere.
- **Errors before the first call.** A strict config, checks of the connection and of the headroom
  for a hanging target, with what to change.
- **A report that says what happened.** Calls by category (overload, target failure, timeout, cut
  off, unreachable and more); error codes split into "from the target" and "from the client"; "at
  300 rps 40% of calls got no answer, from second 25 on none did"; a timeout shown as a lower bound
  (`>500ms`), not a number; warm-up apart.
- **The generator's own share is visible.** How late calls started, waits for a connection and a
  stream, p99 without them — and which of them holds the tail.
- **Honest invalidity.** When the numbers are not about the target (in-flight cap hit, nothing
  measured, the machine's clock too coarse) the run is declared invalid, exit code 2. Ctrl+C stops
  softly and still prints the report.
- **For people and scripts.** A live terminal view, a progress line without a terminal, JSON
  (`schema_version` 1) for CI.
- **Try it without a service of your own.** A reference stand with known behaviour, examples for
  every mode ([quickstart](https://github.com/yhgrwav/leettest/blob/main/docs/en/quickstart.md)),
  a built-in `-fake` target.

### Limits

One connection — behind a load balancer one backend gets the load. Unary only. No ramp-up, CI
thresholds or metrics export yet — [what comes next](https://github.com/yhgrwav/leettest/blob/main/docs/en/roadmap.md).
Measure from Linux next to the target.

Missing something? [Open an issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## Deutsch

Die erste öffentliche Version: Last auf einen gRPC-Dienst und ein Bericht, der nicht lügt, während
der Dienst degradiert.

### Was es kann

- **Last wie in der Produktion.** Mehrere unäre Methoden in einem Lauf, jede mit eigener RPS und
  Dauer. Aufrufe gehen nach Plan raus, auch wenn frühere noch nicht geantwortet haben.
- **Latenz, die Stillstände nicht versteckt.** Gezählt ab dem Zeitpunkt, für den jeder Aufruf
  geplant war; p50/p90/p95/p99 und Maximum je Methode, nie gemittelt.
- **Kein `.proto`.** Methoden und Anfrage-Bodies kommen über Server Reflection vom Dienst; der Body
  ist einfaches YAML in der Konfiguration, geprüft vor dem Start.
- **Zugang zu echten Diensten.** TLS, gegenseitiges TLS, eigene CA, `server_name`; Header mit
  Geheimnissen aus Umgebungsvariablen, deren Werte nirgends ausgegeben werden.
- **Fehler vor dem ersten Aufruf.** Eine strenge Konfiguration, Prüfung der Verbindung und der
  Reserve für ein hängendes Ziel, mit dem, was zu ändern ist.
- **Ein Bericht, der sagt, was passiert ist.** Aufrufe nach Kategorie (Überlastung, Fehler des
  Ziels, Timeout, abgeschnitten, nicht erreichbar u. a.); Fehlercodes getrennt nach „vom Ziel" und
  „vom Client"; „bei 300 RPS bekamen 40 % der Aufrufe keine Antwort, ab Sekunde 25 keiner mehr";
  ein Timeout als Untergrenze (`>500ms`), nicht als Zahl; Aufwärmen getrennt.
- **Der Anteil des Generators ist sichtbar.** Wie spät Aufrufe starteten, Warten auf Verbindung und
  Stream, p99 ohne sie — und was davon das Ende der Verteilung hält.
- **Ehrliche Ungültigkeit.** Handeln die Zahlen nicht vom Ziel (Grenze erreicht, nichts gemessen,
  zu grobe Uhr der Maschine), wird der Lauf für ungültig erklärt, Exit-Code 2. Ctrl+C hält sanft an
  und gibt trotzdem den Bericht aus.
- **Für Menschen und Skripte.** Eine Live-Ansicht im Terminal, eine Fortschrittszeile ohne Terminal,
  JSON (`schema_version` 1) für CI.
- **Ausprobieren ohne eigenen Dienst.** Ein Referenz-Stand mit bekanntem Verhalten, Beispiele für
  jeden Modus ([Schnellstart](https://github.com/yhgrwav/leettest/blob/main/docs/de/quickstart.md)),
  ein eingebautes Scheinziel `-fake`.

### Grenzen

Eine Verbindung — hinter einem Load Balancer bekommt ein Backend die Last. Nur unär. Noch kein
Hochfahren, keine CI-Schwellen, kein Metrik-Export —
[was als Nächstes kommt](https://github.com/yhgrwav/leettest/blob/main/docs/de/roadmap.md). Messen
Sie von Linux aus neben dem Ziel.

Fehlt Ihnen etwas? [Eröffnen Sie ein Issue](https://github.com/yhgrwav/leettest/issues/new/choose).

## 简体中文

第一个公开版本：对 gRPC 服务施加负载，并在服务退化时给出不说谎的报告。

### 功能

- **接近生产的负载。** 一次运行中多个 unary 方法，各有自己的 RPS 和时长。即使之前的调用尚未应答，
  调用也按计划发出。
- **不掩盖卡顿的延迟。** 从每个调用被计划的时刻开始计算；按方法给出 p50/p90/p95/p99 和最大值，
  从不做平均。
- **不需要 `.proto`。** 方法和请求体通过 server reflection 从服务获取；请求体是配置中的普通 YAML，
  在启动前检查。
- **访问真实服务。** TLS、双向 TLS、自定义 CA、`server_name`；带机密的请求头取自环境变量，其值在
  任何地方都不会输出。
- **错误发生在第一次调用之前。** 严格的配置，检查连接以及应对目标挂起的余量，并说明应修改什么。
- **报告说明发生了什么。** 调用按类别划分（过载、目标故障、超时、截断、不可达等）；错误代码分为
  “来自目标”和“来自客户端”；“以 300 RPS，40% 的调用没有得到应答，从第 25 秒起全部没有应答”；
  超时显示为下界（`>500ms`），而不是数字；预热单独统计。
- **压测机自身的影响清晰可见。** 调用启动晚了多少、等待连接和流的时间、去掉这些等待后的 p99——
  以及其中哪一项决定了尾部。
- **诚实地判定无效。** 当数字与目标无关时（触及上限、没有测到任何内容、机器时钟太粗），运行被
  判为无效，退出码 2。Ctrl+C 温和停止，并仍然输出报告。
- **面向人和脚本。** 终端中的实时界面，没有终端时的进度行，供 CI 使用的 JSON（`schema_version` 1）。
- **无需自己的服务即可试用。** 行为已知的参考测试台，覆盖每种模式的示例
  （[快速上手](https://github.com/yhgrwav/leettest/blob/main/docs/zh-CN/quickstart.md)），内置的
  `-fake` 假目标。

### 限制

一条连接——在负载均衡器后面只有一个后端承受负载。仅支持 unary。尚无爬坡、CI 阈值和指标导出——
[接下来会有什么](https://github.com/yhgrwav/leettest/blob/main/docs/zh-CN/roadmap.md)。请在目标旁边
的 Linux 上测量。

缺少某项功能？[提交 issue](https://github.com/yhgrwav/leettest/issues/new/choose)。
