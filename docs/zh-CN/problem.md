# LeetTest 解决什么问题？

[← 返回文档](README.md)

> 译自 [docs/ru/problem.md](../ru/problem.md)，对应 feb2d1d，2026-11-10。如有出入，以俄文版为准。
> **可能滞后：** 中文版在每次发布前同步，最新内容请看[英文版](../en/problem.md)。

压测是为了回答一个问题：**服务在多大负载下开始扛不住，瓶颈在哪里。**
拿着这个答案去找开发者——修复、优化、决定是否发布。

要让答案真实，需要两样东西。

**由多个方法组成的负载。** 运行中的服务会同时收到不同方法的调用：例如很多余额查询、较少的转账、
极少的注册。这些方法可能共用连接池、数据库锁和缓存，因此每个方法单独施压得到的结果，可能与混合
负载不同（这个例子是虚构的，不是测量）。`ghz` 的一次运行只给一个方法施压[（来源）](why.md#来源)；
LeetTest 描述完整的负载：一个方法列表，每个方法各自的 RPS，一次运行，一份报告。

**带有明示限制的数字。** 压测工具给出的数字是决策的依据。带有测量误差的数字看起来与正确的数字
一样，因此报告会把请求的负载与实际给出的负载并排显示，并指出客户端侧的等待。有哪些测量误差，
以及 LeetTest 如何处理它们，见[单独一页](pitfalls.md)。

工具不做的事：它只从外部观察服务——延迟、吞吐、错误。它看不到服务的 CPU 和内存，
也不会从自身数据中猜测它们。这些数据来自服务的监控，按时间与负载对齐。
