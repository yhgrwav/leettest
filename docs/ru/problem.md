# Какую проблему решает LeetTest?

[← К документации](README.md)

Нагрузочный тест нужен, чтобы ответить на один вопрос: **при какой нагрузке сервис перестаёт
справляться и где узкое место.** С этим ответом идут к разработчикам — чинить, оптимизировать,
решать, выпускать ли релиз.

Чтобы ответ был правдой, нужны две вещи.

**Нагрузка из нескольких методов.** Сервис в работе получает вызовы разных методов одновременно:
например, много запросов баланса, меньше переводов, совсем мало регистраций. Методы могут делить
пул соединений, блокировки в базе и кеш, поэтому нагрузка на каждый метод по отдельности может
дать другой результат, чем смесь (пример выдуманный, не измерение). Один запуск `ghz` нагружает
один метод [(источник)](why.md#источники); LeetTest описывает нагрузку целиком: список методов, у
каждого свой RPS, один прогон, один отчёт.

**Числа с видимыми ограничениями.** Нагрузочный инструмент выдаёт число, на основании которого
принимают решение. Число, полученное с ошибкой измерения, выглядит так же, как верное, поэтому
отчёт показывает запрошенную нагрузку рядом с выданной и называет ожидания на стороне клиента.
Какие бывают ошибки измерения и как с ними обращается LeetTest — на
[отдельной странице](pitfalls.md).

Чего инструмент не делает: он видит сервис только снаружи — задержки, пропускную способность,
ошибки. Загрузку CPU и памяти сервиса он не видит и не угадывает по своим данным. Её берут из
мониторинга сервиса и сопоставляют с нагрузкой по времени.
