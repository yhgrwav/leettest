# Подключение

[← К документации](../README.md)

Как LeetTest находит ваш сервис и входит в него: адрес, шифрование, заголовки с токеном и схема
методов. Всё, что можно проверить до нагрузки, проверяется до старта: при ошибке код выхода 1 и ни
одного запроса к сервису.

## Минимальный конфиг

```yaml
app:
  target:
    ip: 10.0.3.17
    port: 443
  ca: certs/ca.pem            # пути — относительно файла конфига
  cert: certs/client.pem
  key: certs/client.key
  server_name: payments.internal
  metadata:
    authorization: Bearer ${PAYMENTS_TOKEN}
    x-api-key: ${PAYMENTS_KEY}
```

- `target` — адрес сервиса: `ip` (имя или IP) и `port`.
- `tls` — не указан: шифрование включено. `tls: false` — подключение без шифрования.
- `ca` — файл PEM с сертификатами, которым проверять сервис вместо системных. Нужен TLS.
- `cert` и `key` — клиентский сертификат и его ключ в PEM, для сервиса с mTLS. Только вместе.
- `server_name` — имя, по которому проверять сертификат сервиса, если он не называет адрес из
  `target`.
- `metadata` — заголовки каждого запроса: `authorization`, `x-api-key` и другие.

Каждое поле — в [справочнике](../reference.md#конфиг).

## Токены и секреты

`${ИМЯ}` подставляется из переменной окружения, в том числе внутри значения: `Bearer ${TOKEN}`.

```sh
export PAYMENTS_TOKEN=значение-токена
export PAYMENTS_KEY=значение-ключа
leettest -c leettest.yaml
```

- Переменная не задана или пуста — ошибка до старта с её именем. Иначе ушёл бы `Bearer ` без
  токена, и прогон показал бы 100% отказов как вину сервиса.
- Подстановка работает только в `metadata`. Флага для заголовков нет, поэтому токен не попадает ни в
  `ps`, ни в историю shell.
- Значения заголовков LeetTest не печатает нигде: ни в отчёте, ни в ходе прогона, ни в ошибках.
- Чтобы написать `${` буквально, удвойте доллар: `$${`.
- Имена заголовков приводятся к нижнему регистру. Ошибка конфига: ключ с `grpc-`, псевдозаголовки
  вроде `:path`, ключ с `-bin`, `content-type`, `te`, `connection`, `keep-alive`,
  `proxy-connection`, `transfer-encoding`, `upgrade`, значение вне печатаемого ASCII.

## Что появится в отчёте

- Проверка сертификата сервиса не отключается ничем. `ca` заменяет системные корни, а не
  добавляется к ним. `server_name` меняет только имя, с которым сверяется сертификат; зашифрованный
  паролем ключ не поддерживается — расшифруйте заранее.
- Сервис ответил на проверке `Unauthenticated`, а заголовки заданы: прогон не начнётся, ошибка
  «target rejected credentials». `PermissionDenied` прогон не останавливает: токен принят, но
  методы помечаются непроверенными. `Unauthenticated` без заголовков тоже не останавливает, в
  заметке сказано: «target requires credentials; app.metadata is not set».
- Несколько соединений: по умолчанию одно соединение попадает в один сервер, а за L4-балансировщиком
  (Kubernetes ClusterIP, NLB) или при нескольких адресах в DNS нагружается только он, и отчёт этого
  не покажет. `app.connections: N` открывает N соединений, а отчёт печатает блок `Connections:`:
  адрес, запросы, долю отказов и p99 на каждое. Подробности — в
  [справочнике](../reference.md#доступ-к-сервису).

## Схема методов: reflection или .proto

По умолчанию схему LeetTest берёт у сервиса через gRPC server reflection, `.proto` не нужен. Если
reflection выключен, метод с `data` не запустится: ошибка скажет это прямо. Два выхода:

- убрать `data`: уйдёт пустое сообщение, метод не проверен, об этом печатается предупреждение;
- дать схему файлом (с v0.3): `app.proto` (файлы и `import_paths`, где искать их импорты) или
  `app.protoset` (набор дескрипторов, собранный `protoc --include_imports`) —
  [`examples/ru/proto.yaml`](../../../examples/ru/proto.yaml),
  [`examples/ru/protoset.yaml`](../../../examples/ru/protoset.yaml).

## Частые ошибки

- **TLS включён, а сервис без шифрования** (или наоборот): ошибка до старта. Поставьте или уберите
  `tls: false`.
- **Сертификат сервиса не называет адрес.** Ошибка подскажет `server_name`.
- **Сервис закрыл соединение сразу после рукопожатия.** Он не принял клиентский сертификат: проверьте
  `cert` и `key`.
- **Файл сертификата не найден или не PEM, сертификат не подходит к ключу, сертификат просрочен.**
  Все эти ошибки приходят до первого запроса.
- **Адрес `localhost`, а сервис слушает только `127.0.0.1`.** Имя может раскрыться в `::1`; укажите
  IP.
- **Токен написан значением в конфиге.** Хеш конфига в отчёте покажет любую правку файла, а сам
  токен окажется в репозитории: пишите `${ИМЯ}`.
