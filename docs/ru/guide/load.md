# Нагрузка

[← К документации](../README.md)

Какие методы, с какой частотой и как долго нагружать. LeetTest держит заданный темп запросов в
секунду, даже если сервис отвечает медленнее: запрос уходит по расписанию, не дожидаясь предыдущих,
а задержка считается от запланированного момента.

## Минимальный конфиг

```yaml
app:
  target:
    ip: localhost
    port: 50051
  tls: false

load:
  warmup: 5s
  ramp: 30s
  calls:
    - method: wallet.v1.WalletService/GetBalance
      rps: 800
      duration: 1m
      timeout: 500ms
      data:
        wallet_id: "w-123"

    - method: wallet.v1.WalletService/Transfer
      rps: 50
      duration: 1m
```

```sh
leettest -c leettest.yaml
```

- `method` — полное имя: `пакет.Сервис/Метод`. Один метод — один вызов в `calls`; несколько
  методов с разным темпом — несколько вызовов.
- `rps` — целое число запросов в секунду. `10.5` отклоняется, а не округляется молча.
- `duration` — сколько нагружать метод: `30s`, `5m`, `1h`.
- `timeout` — сколько ждать ответа. Не указан — `2s`. Ноль не отключает тайм-аут, а даёт ошибку.
- `warmup` — первые секунды идут к сервису, но не попадают в статистику, потому что холодные кеши
  её портят. Прогрев входит в `duration` и должен быть короче каждого вызова. В отчёте он стоит
  отдельной строкой `warm-up N sent`.
- `ramp` — разгон: каждый метод поднимается с нуля до своего `rps` линейно за это время, а потом
  начинается его `duration`. Прогон идёт `ramp` + `duration` (`warmup`, если задан, входит в `duration`). Запросы разгона не попадают в
  статистику; пределы `pass` и доля ошибок считаются только по удержанию. Пример —
  [`examples/ru/ramp.yaml`](../../../examples/ru/ramp.yaml).
- `data` — тело запроса обычным YAML в форме сообщения. Нет `data` — уходит пустое сообщение.

Все запросы метода уходят с одним и тем же телом. Для записи с ключом идемпотентности это значит,
что создаёт запись только первый запрос, а остальные идут по пути повтора: меряется он. Другой
запрос на каждый вызов — файл `dataset` (по одному JSON на строку) или `templates: true` с
`{{uuid}}` и `{{seq}}`; см. [справочник](../reference.md#тело-запроса).

## Что появится в отчёте

- Строка на метод: `sent`, `failed`, `sent/s` и перцентили. Под ней `plan:` — темп и длительность,
  которые вы задали.
- `sent/s` — отправленные запросы, делённые на время отправки: подвисание сервиса в конце прогона
  не занижает эту цифру.
- Если запросов ушло меньше, чем в `plan:`, отчёт говорит, почему: `not sent` с причиной.
- Блок `over time` под таблицей метода показывает, как менялись темп, доля отказов, p50 и p99 по
  окнам времени. С `ramp` первые строки — это разгон: низкий `sent/s` там запланирован, а не
  сломался. Смотрите строку, где p99 или доля отказов растут раньше, чем темп вышел на плато.
- Когда сервис завис, строка под таблицей называет секунду, после которой он не ответил ни на один
  запрос.

Как читать каждую часть — [Как читать отчёт](../report.md#как-читать-отчёт).

## Перед стартом

LeetTest проверяет конфиг до первого запроса: неизвестное поле, неверное значение, метод, которого
нет у сервиса, ошибка в теле запроса — код выхода 1 и ни одного запроса к сервису. Проверка потолка
запросов без ответа: сервис, который завис, держит `rps × timeout` запросов, и сумма по методам не
должна превышать `-max-in-flight` (по умолчанию 5000). Ошибка называет оба выхода: какой тайм-аут
влезет и какой нужен потолок.

## Частые ошибки

- **`warmup` длиннее или равен `duration`.** От вызова не осталось бы ни одного измеренного
  запроса: ошибка конфига.
- **Нужен «рост» нагрузки, а задан сразу `rps`.** Без `ramp` метод стартует на полном темпе. Для
  роста задайте `ramp`; чтобы узнать, при какой нагрузке сервис перестаёт справляться, —
  [поиск точки отказа](../report.md#поиск-точки-отказа).
- **Тайм-аут слишком большой для потолка.** Ошибка до старта, см. выше.
- **Тайм-аут слишком короткий.** Запросы, не успевшие ответить, оборвутся по тайм-ауту и покажутся
  отказами сервиса; их перцентиль печатается как `>500ms` — «не меньше 500 мс».
- **Каждый запрос одинаковый, а нужны разные.** См. выше про `dataset` и `templates`.
- **Запуск через ssh без терминала.** Добавьте `-plain`: строка прогресса раз в секунду вместо
  живого экрана.
